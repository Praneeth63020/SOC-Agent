# Test scenarios (SYNTHETIC)

Each folder is a complete **data root** that the tools read for one run (`RunContext.data_dir`): `alert.json`, `logs/` (Wazuh + tshark), `intel/` (**MOCK** feed, `live: false`), `assets/` (inventory) and `scenario.json` (title, description, fault injection, tool timeout). Everything is **SYNTHETIC lab data**: RFC 5737 / RFC 1918 addresses and invented names. The folders are generated by [`scripts/make_synthetic_logs.py`](../../scripts/make_synthetic_logs.py), deterministically. The expected outcomes are in [`tests/scenarios/<name>/expected.yaml`](../../tests/scenarios/).

| Scenario | Brief category | What the evidence shows | Expected |
|---|---|---|---|
| `normal` | normal | one mistyped password (a low-level Wazuh alert, rule 5760) from the office IP 10.20.1.45, then j.mehta's usual publickey login; ordinary work after | low; benign hypothesis supported; no containment |
| `compromise` | suspicious | the main case (same files as `data/logs`): 3 failures for a.rao, then 50 for j.mehta from 203.0.113.77; success; sudo; `useradd backup_svc`; 48 MB outbound to 198.51.100.23 (MOCK: suspicious) | high/critical; benign hypothesis refuted |
| `benign` | benign | j.mehta mistypes the password 4 times from the office IP 10.20.1.45 (2 SSH connections), then logs in; normal HTTPS / database traffic after | low; benign hypothesis supported; no MITRE for attacks |
| `failures_only` | additional | 50 failures from 203.0.113.77, no success | low/medium; no T1078 |
| `incomplete` | incomplete | 30 failures, success and sudo on **fin-app-02, which is not in the inventory**; **no tshark export** | confidence not high; both gaps stated |
| `tool_failure` | tool failure | the main data; **lookup_ip times out** (fault injection, testing only) | reputation stated as unknown; confidence not high |
| `tool_failure_logs` | tool failure | the main data, but `wazuh_alerts.jsonl` is damaged (bytes that are not UTF-8): `search_logs` cannot read it; tshark, MOCK intel and the inventory still answer | failure stated as a gap and an unknown; no Wazuh ref cited; confidence not high; no containment justified |
| `conflicting` | additional | 50 failures + success, but the capture holds only 6 of the failed SSH sessions | the tshark vs Wazuh conflict is reported; confidence not high |

Run one scenario:

```bash
python -m soc_agent analyze data/scenarios/benign/alert.json --data-dir data/scenarios/benign --provider mock
SOC_TOOL_TIMEOUT_S=1 python -m soc_agent analyze data/scenarios/tool_failure/alert.json --data-dir data/scenarios/tool_failure \
    --provider mock --scenario analyze_tool_failure
```

Each scenario also says whether containment must be requested (`containment: requested | none | any` in `expected.yaml`, checked after the report phase).

To run the whole matrix end to end (plan -> assess -> report, plus the rejection and safety runs): `python scripts/run_scenarios.py` -> `reports/scenarios-mock.json`, summarized in [`docs/test-report.md`](../../docs/test-report.md).
