# Evidence data (Day 2)

Everything here is **SYNTHETIC lab data** (logs, assets) or **MOCK** (intelligence). It was fabricated for the Cehpoint assessment, uses RFC 5737 documentation addresses for "internet" IPs and RFC 1918 addresses for internal ones, and only invented names. No real system was captured or queried.

Scenario (same as [`data/alerts/`](../alerts/)): 50 failed SSH logins for `j.mehta` on `fin-app-01` (10.20.5.17) from `203.0.113.77` between 2026-11-18T09:31:02Z and 09:41:55Z, then an accepted password login from the same IP at 09:42:17Z.

| File | Read by | Label | What it contains |
|---|---|---|---|
| `data/logs/wazuh_alerts.jsonl` | `search_logs` (source `wazuh`) | SYNTHETIC | Wazuh `alerts.json` export, one alert per line (line 1 is a `_comment` header) |
| `data/logs/tshark_sessions.csv` | `search_logs` (source `tshark`) | SYNTHETIC | tshark field export of TCP sessions, plus `duration_s` and `bytes` (line 1 is a `#` comment) |
| `data/intel/ip_reputation.json` | `lookup_ip` | MOCK | IP reputation records (score, categories, report count, first/last seen, ASN, country) |
| `data/intel/cve_db.json` | `search_cve` | MOCK | a few OpenSSH CVEs with affected version ranges, CVSS and a summary |
| `data/assets/inventory.json` | `get_asset_context`, `search_logs` (IP → host names for tshark) | SYNTHETIC | hosts (role, criticality, owner, OS, services and versions, internet exposure) and accounts (role, privileged flag, usual locations / IPs) |

The two log files are generated by [`scripts/make_synthetic_logs.py`](../../scripts/make_synthetic_logs.py) (deterministic: running it again gives the same bytes). The JSON files are hand-written.

## Export command (what a real capture would go through)

```bash
# one row per TCP connection start (SYN without ACK)
tshark -r lab_capture.pcapng -Y "tcp.flags.syn==1 && tcp.flags.ack==0" \
  -T fields -E header=y -E separator=, -E quote=d \
  -e frame.time_epoch -e ip.src -e tcp.srcport -e ip.dst -e tcp.dstport -e tcp.stream \
  > sessions_fields.csv
# per-conversation duration and bytes, joined on tcp.stream to add duration_s and bytes
tshark -r lab_capture.pcapng -q -z conv,tcp
```

## Evidence references

Every record a tool returns carries an `evidence_ref` that points back to exactly one place in these files:

| Ref | Points at |
|---|---|
| `wazuh_alerts.jsonl#L57` | physical line 57 of the file (1-based, header line included) |
| `tshark_sessions.csv#row12` | the 12th data row below the CSV header (comment and header lines not counted) |
| `ip_reputation.json#203.0.113.77` | that record in the intel feed |
| `cve_db.json#CVE-2024-6387` | that CVE entry |
| `inventory.json#hosts/fin-app-01`, `inventory.json#accounts/j.mehta` | that inventory record |

`soc_agent.tools.evidence.resolve_ref()` returns the raw record behind a ref. On Day 2 the evidence log may only cite refs that a tool actually returned in the same run.

**Why both log sources:** SSH is encrypted, so tshark shows how many connections came from `203.0.113.77`, when, for how long and how many bytes, and what else the server talked to. It cannot show whether a password was right or wrong. Login success or failure comes from Wazuh / `auth.log`.
